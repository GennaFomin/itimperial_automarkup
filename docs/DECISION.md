# Praxis — окончательный выбор алгоритма

Дата: 2026-09-03. Это итог всех замеров недели. Ниже — что представляем, почему, с
какими числами и где остаётся риск.

## Решение

**Границы шагов ставит обучаемый class-agnostic детектор (`learned-boundaries`),
метки шагам даёт Qwen3-VL-8B свободной генерацией без словаря. Ядровой change-point
(`tsm-kernel`) остаётся за тем же интерфейсом как запасной сегментатор и как режим
для крупной гранулярности.** Гранулярность — ручка на уровне API, не константа.

Детектор не знает классов по построению: его единственный обучающий сигнал —
момент смены действия, из разметки берутся только таймкоды. Требование кейса «любое
действие, любой объект, словаря нет» выполняется на обоих концах: границы без классов,
имена без словаря.

## Детектор границ: итоговая архитектура (2026-09-05)

**Выбрано: ансамбль из двух MS-TCN (2 стадии, 64 фильтра, 10 слоёв на стадию, один
логит «здесь смена действия») на голых признаках TimeSformer-K400 (768, окно 0.5 с при
32 fps, шаг 4 кадра = 8 Гц), усреднение вероятностей по кадрам, декодер — пики выше 0.7
с интервалом 0.5 с.** Участники: fine604 (554 ролика Assembly101 fine) и fine604 + 60
эпизодов LIBERO. Один файл `checkpoints/boundary.pt`, сервис читает `members`. Полные
таблицы: `experiments/results/2026-09-05-boundary-final.md`.

| набор | база (что было в main) | ансамбль |
| --- | --- | --- |
| 85 атомарных роликов Assembly101 fine, сессии вне обучения | 0.422 | **0.498** |
| EPIC-100, средний режим, 16 роликов | 0.413 | **0.535** |
| робот LIBERO, держ-аут, 10 эпизодов | 0.096 | **0.733** |

Продуктовые метрики на атомарном режиме: 90 % наших разрезов лежат в 2 с от эталонной
границы (83 % — в 1 с), средняя ошибка совпавших границ 0.28 с, число шагов на ролик
совпадает с эталоном (Δ −0.2); step-F1 при IoU 0.25 — 0.71.

Почему именно так — по пунктам, каждый подтверждён замером:

1. **Класс-агностичный MS-TCN на видеопризнаках.** Единственный сигнал обучения —
   таймкоды смен; словарь классов не нужен ни при обучении, ни при выводе. Это
   требование кейса, и оно же позволяет учить на любой размеченной по времени выборке.
2. **Две стадии, σ = 2 кадра, без каналов движения и разностей.** Четыре стадии, σ 1 или 3,
   полоса движения, разностные каналы, аугментация C2F-TCN и TTA — всё внутри шума
   инициализаций (±0.01) на атомарном режиме; голые 768 признаков ещё и совпадают с тем,
   что main уже отправляет детектору.
3. **Окно признаков 0.5 с при 8 Гц вместо 1 с при 4 Гц.** Единственное изменение дня,
   которое двигает атомарный режим: 0.478 против 0.427 на той же модели и корпусе.
   Пики становятся достаточно острыми для интервала 0.5 с, и находятся шаги короче
   секунды. Цена — вдвое больше окон энкодера на ролик.
4. **Ансамбль из fine-модели и fine-модели с роботом.** На своём режиме пара внутри шума от
   лучшей (0.498 против 0.501), но одиночная fine-модель режет робота на десять частей
   (0.06–0.15), а участник, видевший 60 роботных эпизодов (10 % корпуса), держит 0.73 и
   не теряет на атомарном. Скрытый набор «может показывать робота» — страховка ровно от
   этого.
5. **Порог 0.7 и интервал 0.5 с.** Для этой пары 0.7 лучше 0.5 на всех трёх наборах
   (0.498 / 0.535 / 0.733 против 0.486 / 0.498 / 0.713); интервал 0.5 с возможен только
   с признаками 8 Гц — на 4 Гц он разваливал результат (0.34–0.38).

Что не сработало и почему это важно: втрое больше данных того же режима — +0.005;
разбор ошибок показывает, что теряются шаги короче 1 с (56 % эталона) и точность самих
разрезов (медианная ошибка 0.52 с при потолке 0.80). Резерв — временное разрешение
признаков и локализация границ; проверка окна 0.5 с при 8 Гц идёт, результат
дописывается ниже.

Приложение извлекает признаки с `PRAXIS_VIDEO_FPS=32`, `PRAXIS_VIDEO_WINDOW=16`,
`PRAXIS_VIDEO_STRIDE=4`, порог `PRAXIS_TAS_THRESHOLD=0.7`, интервал
`PRAXIS_MIN_SEGMENT_SEC=0.5` — всё это умолчания. Не вошло в решение и дообучалось на
момент записи: признаки 8 Гц при окне 1 с, второй роботный seed, энкодер V-JEPA 2; VideoMAE
проиграл TimeSformer на всех наборах, кроме EPIC.

## Что требует кейс и что это значит для алгоритма

| требование | следствие |
| --- | --- |
| атомарные действия: взял, повернул, перенёс, опустил | шаги 1–4 с, границ много — режим плотных границ |
| стол, статичная камера от третьего лица | домен Assembly101 fine и наших снятых роликов |
| ролик 15–30 с | короткие окна, длинные видео не нужны |
| словаря классов нет, открытый набор | никакого обучения на классах, VLM свободной генерацией |
| метрика: IoU ≥ 0.5 + верное действие, precision/recall/F1 | строгий порог по времени — важна точность границы, не только её наличие |
| ключевой кадр на шаг, валидный экспорт | контракт, `keyframe_ms` — сделано и покрыто тестами |

Ключевое: **домен кейса — это режим плотных коротких границ.** Именно на нём детектор
обучен и именно на нём он выигрывает. Его провал на другом режиме (см. ниже) — не
про кейс.

## Что измерено

Нарезка без сверки меток, F1@0.5 (порог кейса). Настройки гранулярности подобраны
под каждый набор и одинаковы для всех методов внутри строки.

| набор | режим | ядровой | **детектор** | равномерная |
| --- | --- | --- | --- | --- |
| Assembly101 fine, 85 роликов | шаг ~1 с, домен кейса | 0.289 | **0.411** (0.385–0.438) | 0.288 |
| Assembly101 coarse, 8 | шаг ~10 с | 0.553 | **0.746** | 0.492 |
| Charades, 90 роликов | быт, шаг ~6 с, человек в движении | **0.507** (0.459–0.553) | 0.355 (0.303–0.410) | 0.627 |
| EPIC-KITCHENS, 4 | налобная камера | 0.192 | 0.400 | 0.617 |

Три вывода:

1. **На домене кейса детектор выигрывает, интервалы не пересекаются.** На атомарной
   сборке 0.411 против 0.289, на крупной разметке той же съёмки 0.746 против 0.553.
2. **На чужом режиме он проигрывает** — Charades: 0.355 против 0.507. Перенос упирается
   в плотность границ (1 с против 6 с), не в таксономию. Это согласуется с литературой:
   детектор, обученный на Kinetics-GEBD, сохраняет ~82 % F1 на процедурном видео с той
   же плотностью и разваливается там, где длительность шагов другая.
3. **Равномерная нарезка сильна на наборах с 2–3 крупными шагами** и разваливается на
   атомарных (0.223–0.288). Она нужна как контроль: бенчмарк, где она выигрывает, не
   про наш домен.

### За счёт чего выигрывает детектор

Границы как точки, 85 атомарных роликов, 1104 эталонных границы:

| | границ поставлено | ±0.25 с recall / precision | ±0.5 с | ±1.0 с |
| --- | --- | --- | --- | --- |
| ядровой | 856 | 0.272 / 0.350 | 0.439 / 0.567 | 0.530 / 0.683 |
| **детектор** | 859 | **0.416 / 0.534** | **0.508 / 0.653** | **0.580 / 0.745** |

Число границ одинаковое. Выигрыш — **точность попадания**: при допуске в четверть
секунды найдено 42 % границ против 27 %. Смещение у обоих нулевое. При пороге
IoU ≥ 0.5 на шагах по секунде ошибка в четверть секунды решает, засчитан шаг или нет —
поэтому именно эта точность и переводится в метрику кейса.

### На наших снятых роликах

Три ролика, снятых нами по постановке кейсодателя (`praxis-pool/test/filmed/`),
разметки нет — проверка глазами, `test/side_by_side.mp4`:

| ролик | ядровой, штраф 2 | детектор, порог 0.7 |
| --- | --- | --- |
| test_bottle | 14 шагов | 7 шагов |
| test_phone | 9 | 8 |
| test_combined | 16 | 6 |

Оба именуют осмысленно: «взял бутылку воды», «повернул бутылку», «вылил воду»,
«перенёс бутылку», «опустил руку». Ядровой режет мельче, потому что штраф 2 — атомарная
настройка; при штрафе 3–5 он даёт 7–9 шагов. Детектор попал в гранулярность сам, без
подбора. Ключевые кадры детектора по `test_combined` совпадают с метками на всех шести
шагах (единственное расхождение — «мыло/салфетка» для зелёной губки).

## Почему не другие

Все числа — F1@0.5 без сверки меток на тех же пулах, подробности в `BOUNDARIES.md`.

- **VLM ставит границы** — бинпоиском 0.198, прямым запросом пересегментация. Лучшие
  VLM на видео манипуляций (WGO-Bench, IoU ≥ 0.75): Gemini 3.5 Flash 0.290. VLM —
  для имён, не для таймкодов.
- **Ансамбль ядрового и детектора** — на домене кейса почти догоняет детектор (0.390
  против 0.411), на чужом наследует его провал (0.357 против 0.507). Не лечит перенос,
  только усложняет.
- **Рекурсивный разбор самоподобия (UBoCo)** 0.251, **TW-FINCH** 0.367, **DP по
  движению** 0.429 при 0.627 у равномерной — все ниже на своих наборах.
- **Замена энкодера** (VideoMAE, V-JEPA 2, DINOv2) — в пределах шума.
- **Обучение на классах / open-vocabulary голова через текстовые эмбеддинги** —
  словаря нет, а у SigLIP2 нет сигнала о глаголе в этом домене (0.060 против 0.660 у
  константы). Отклонено.

## Именование

Qwen3-VL-8B, свободная генерация, 5 кадров на шаг плюс два контекстных «до/после»,
`unknown` разрешён. На эталонных границах Charades по всем допустимым меткам: действие
0.558, объект 0.660 (контекстные кадры — единственный рычаг, давший прирост).

**Оговорка про метрику.** При открытом словаре ответ модели и слово аннотатора
расходятся при верном смысле: `move / to another room` против `run`, `extract / booklet`
против `take / picture`. Сравнение строк меряет лексику, а не восприятие. Первый вопрос
кейсодателю — как засчитываются синонимы; пока наши числа именования занижены.

## Риски и как они закрыты

| риск | что делаем |
| --- | --- |
| скрытый набор размечен крупно | порог детектора 0.95 или ядровой со штрафом 8 — переключение, не переписывание |
| скрытый набор из другого домена | детектор дообучается на границах без классов; сколько роликов нужно — замер не завершён (см. ниже) |
| VLM недоступна | шаг получает `unknown`, прогон помечен деградировавшим, статус виден в API |
| нет GPU на площадке | облачный фолбэк VLM; признаки TimeSformer — самое узкое место, нужен хотя бы один GPU или предрасчёт |
| прогон не укладывается в 2 мин | сейчас 30–70 с на ролик; батч VLM по числу картинок, чекпоинт по стадиям |

## Что не завершено

Два замера убиты перезапуском сессии до результата, DL5 сейчас недоступен:

- **зависимость качества детектора от объёма обучения** (20 / 60 / 203 ролика) — решает,
  сможет ли команда дообучить его на своих съёмках за вечер;
- **дообучение на чужом домене** (Charades train 112 → Charades val 90) — покажет,
  восстанавливается ли перенос малыми данными.

Не влияют на выбор, влияют на план на площадке. Повторить: `scripts/train_boundaries.py
--limit N` и `scripts/sweep.py`.

## Воспроизведение

```bash
export PRAXIS_PIPELINE=learned-boundaries PRAXIS_TAS_THRESHOLD=0.7   # домен кейса
export PRAXIS_OPEN_VOCABULARY=1 PRAXIS_LANGUAGE=ru PRAXIS_CONTEXT_FRAMES=0.6
python scripts/annotate.py --in <ролики> --out /tmp/pred
python scripts/eval.py --gt <эталон> --pred /tmp/pred          # метрика кейса
python scripts/sweep.py --clips ... --gt ... --methods tsm-kernel learned-boundaries
python scripts/eval_boundaries.py --gt ... --pred kernel=... learned=...
```

Веса детектора: `checkpoints/boundary.pt` на DL5, сервис `serve_tas.py` (порт 8104),
обучение 5 минут на 203 роликах. Статьи — `experiments/research/papers/`.
