# Praxis — отчёт по валидации для команды

Кому: Саша (алгоритмы), Гена (интеграция и тест). Что здесь: какая метрика, как её
считать у себя, какие числа у нас сейчас и куда они разложены по источникам.

## 1. Метрика — ровно правило кейсодателя

> One-to-one matching: temporal IoU ≥ 0.5 + правильный класс действия.
> Затем считаем precision, recall и F1.

Что это значит на практике:

- каждый эталонный шаг может совпасть только с одним предсказанным и наоборот;
- совпадение засчитывается, если пересечение по времени ≥ 50 % от объединения **и**
  действие названо верно; объект в правило матчинга не входит;
- precision = совпавшие / все предсказанные, recall = совпавшие / все эталонные.

Шаг с идеальными границами и неверным глаголом — промах. Поэтому нарезка и именование
это **одна** метрика, и она раскладывается почти точно в произведение:
`F1 ≈ F1_нарезки × точность_действия`. Улучшать надо ту половину, что ниже.

### Как посчитать у себя

```bash
cd /mnt/data/praxis
python scripts/annotate.py --in /mnt/data/praxis-pool/validation/clips/<источник> --out /tmp/pred
python scripts/eval.py --gt /mnt/data/praxis-pool/validation/annotations/<источник> --pred /tmp/pred
```

`eval.py` печатает три числа: метрику кейса, ту же нарезку **без сверки меток**
(потолок, если бы именование было идеальным) и по паре «действие+объект». Разрыв между
первым и вторым — цена семантики.

Чтобы сравнивать алгоритмы нарезки без именования: `scripts/sweep.py`. Только
границы, как точки, с допуском: `scripts/eval_boundaries.py`.

**Обязательно:** гранулярность — параметр. Один набор настроек на все источники даёт
ложные выводы (см. §4). Сравнивать алгоритмы можно только при одинаковых настройках
на одном источнике.

## 3. Нарезка по источникам, без сверки меток

F1 при IoU 0.1 / 0.25 / 0.5. Настройки гранулярности выставлены под каждый источник
(одинаковые для всех трёх методов внутри строки).

| источник | ядровой change-point | обучаемый детектор | равномерная |
| --- | --- | --- | --- |
| assembly101-fine | 0.715 / 0.598 / 0.309 | 0.700 / 0.635 / **0.394** | 0.699 / 0.576 / 0.223 |
| assembly101-coarse | 0.705 / 0.674 / 0.553 | 0.788 / 0.788 / **0.746** | 0.783 / 0.783 / 0.492 |
| charades | 0.674 / 0.674 / 0.426 | 0.656 / 0.656 / 0.255 | 0.832 / 0.832 / **0.655** |
| epic-kitchens | 0.761 / 0.716 / 0.192 | 0.761 / 0.716 / 0.400 | 0.872 / 0.822 / **0.617** |

На больших выборках (85 атомарных, 90 Charades), где интервалы узкие:

| набор | ядровой | обучаемый | равномерная |
| --- | --- | --- | --- |
| Assembly101 fine, 85 роликов | 0.289 | **0.411** (0.385–0.438) | 0.288 |
| Charades, 90 роликов | **0.507** (0.459–0.553) | 0.355 (0.303–0.410) | 0.627 |

Читать это надо так:

1. **Обучаемый детектор выигрывает там, где плотность границ похожа на обучающую**
   (Assembly101: шаг ~1 с), и **проигрывает на чужом домене** (Charades: шаг ~6 с).
   Он обучен только на границах, классов не видит — переносится по построению, но
   перенос упирается в длительность шагов, не в таксономию.
2. **Равномерная нарезка сильна на наборах с 2–3 крупными шагами** — там она попадает
   по построению. На атомарных действиях она разваливается (0.223).
3. Ядровой change-point — самый ровный: нигде не лучший, нигде не худший.

## 4. За счёт чего выигрывает обучаемый

Разбор границ как точек на 85 атомарных роликах (1104 эталонных границы):

| | границ поставлено | ±0.25 с recall / precision | ±0.5 с | ±1.0 с |
| --- | --- | --- | --- | --- |
| ядровой | 856 | 0.272 / 0.350 | 0.439 / 0.567 | 0.530 / 0.683 |
| обучаемый | 859 | **0.416 / 0.534** | **0.508 / 0.653** | **0.580 / 0.745** |

Число границ одинаковое — выигрыш **не за счёт количества, а за счёт точности
попадания**: при допуске в четверть секунды он находит 42 % границ против 27 %. Классы
не участвуют.

## 5. Именование

Свободная генерация Qwen3-VL-8B без словаря, 5 кадров на шаг плюс два контекстных
«до/после». На эталонных границах, по всем допустимым меткам, Charades 90 роликов:

| | действие | объект | пара |
| --- | --- | --- | --- |
| базовый | 0.523 | 0.660 | 0.386 |
| + контекстные кадры | **0.558** | 0.660 | **0.426** |
| 8 кадров вместо 5 | 0.142 | 0.406 | 0.107 |

**Главная проблема метрики при открытом словаре:** модель отвечает
`move / to another room`, эталон — `run`; `extract / booklet` против `take / picture`.
Ответы верные по смыслу и не совпадают по строке. Точное сравнение строк меряет
лексику аннотатора, а не восприятие. Пока у нас нет семантической сверки — числа
именования на открытом словаре занижены, и насколько — неизвестно. Это первое, что
надо спросить у кейсодателя: как они засчитывают синонимы.

Grounding DINO, SigLIP2, восемь кадров.
