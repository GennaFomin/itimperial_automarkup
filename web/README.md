# Automarkup — предразметка действий по видео

Интерфейс для проверки и правки автоматической сегментации видео на действия.
Модель даёт черновик, человек за минимальное число движений доводит его до
разметки, пригодной для обучения роботов.

Собран против контракта `contracts.md` (`schema_version 1.0`) и подключён к
пайплайну через слой `/api/v1` — см. [docs/CONTRACT_V1.md](../docs/CONTRACT_V1.md).

## Быстрый старт

Интерфейс собирается в `web/dist` и раздаётся тем же процессом, что и API, —
в докере это один контейнер без nginx.

```bash
# из корня репозитория
docker compose up --build            # http://localhost:8000
```

Для разработки — бэкенд и Vite рядом:

```bash
uv venv .venv --python 3.12 && uv pip install --python .venv/bin/python -e ".[dev]"
PRAXIS_PIPELINE=stub .venv/bin/python -m uvicorn praxis.api:app --port 8000

cd web && npm install && npm run dev  # http://localhost:5173
```

Порт 5173 обязателен: `/api` проксируется на `127.0.0.1:8000`, а CORS в
`praxis/api.py` разрешает только его. Через прокси фронт и бэкенд выглядят одним
origin, поэтому preflight на `POST` и `PUT` не возникает.

Из внешнего нужен только **ffmpeg**. `PRAXIS_PIPELINE=stub` работает вообще без
моделей; `tsm-kernel` без GPU-сервисов даёт настоящую нарезку на серых признаках
и шаги без названий, честно сообщая об этом в `warnings`.

### Работа без бэкенда

```bash
npm run dev:mock
```

Мок с фикстурами включается только явно (`VITE_API_MOCK=1`). Он нужен для
состояний, которые живой пайплайн по требованию не воспроизводит: пустой
результат, деградировавший прогон, упавшая задача, обработка дольше десяти
минут. Видео в этом режиме нет — плеер говорит об этом словами, а разметка,
таймлайн и экспорт работают как обычно.

## Два экрана

**Список задач.** Карточка показывает словарь действий, длину ролика и статус
авторазметки. Загруженное видео сразу уходит в очередь; задача открывается,
когда прогноз готов. При создании можно взять общий словарь, ранее сохранённый
или ввести новый (по одному классу в строке, либо `pick — Взять` с явным id).

**Экран разметки.** Видео слева, таймлайн под ним, рабочая панель справа.

## Как правится разметка

Принцип из кейса: граница, действие, объект и ключевой кадр правятся
**независимо** — единой кнопки «переделать всё» нет.

| Задача | Как |
|---|---|
| Найти нужный кадр | колесо над таймлайном — масштаб от всего ролика до 0,4 с в окне |
| Прокрутка при зуме | `Shift`+колесо, перетаскивание ПКМ, обзорная полоса сверху |
| Пробежать разметку глазами | панель ключевых кадров: клик по кадру выделяет сегмент и прыгает на него |
| Разрезать сегмент | поставить курсор и нажать `S` |
| **Вырезать середину** | инструмент «Вырезать» (`C`), протянуть по нужному куску — даже поверх существующих сегментов — и выбрать класс во всплывшем окне |
| Сдвинуть границу | тянуть за край сегмента, либо ввести таймкод в инспекторе |
| Сменить класс | цифры `1`–`9` или чипы в инспекторе |
| Отменить | `Ctrl+Z` / `Ctrl+Shift+Z`, история на 100 шагов |

Вырез — главный инструмент: диапазон может накрывать несколько сегментов и
дыры, всё перекрытое подрезается, полностью накрытое удаляется, на месте выреза
появляется один новый сегмент с выбранным классом.

### Горячие клавиши

`Пробел` играть/пауза · `,` `.` кадр назад/вперёд · `←` `→` ±1 с (`Shift` ±5 с) ·
`Tab` следующий сегмент · `S` разрезать · `C` / `V` инструменты · `F` приблизить
сегмент · `0` весь ролик · `+` `−` масштаб · `1`–`9` действие · `Del` удалить ·
`Ctrl+Z` отмена.

## Как это соединено с пайплайном

UI говорит с бэкендом через слой `/api/v1` — проекцию `contracts.md` поверх
внутреннего API praxis. Что совпало, что расходится и почему — в
[docs/CONTRACT_V1.md](../docs/CONTRACT_V1.md).

Существенное для интерфейса:

- **Видео и кадры отдаёт сервер.** `/media` и `/frame?ms=` — поэтому разметка
  переживает перезагрузку вкладки, а превью ключевых кадров не требуют второго
  декодера видео в браузере.
- **Половина уверенностей приходит `null`.** Пайплайн измеряет одно число на шаг
  — уверенность именования пары «действие + объект». Уверенности границ и
  ключевого кадра он не производит, и вместо выдуманных значений отдаёт пустоту.
  Блок `capabilities` в прогнозе называет это явно, и UI просто не рисует шкалу.
- **Словарь открытый.** Модель отвечает своими словами, поэтому значения вне
  списка — норма: они показываются как есть, с предупреждением, а цвет для
  таймлайна выводится из самого названия.
- **Ограничения ролика приходят с сервера** (`/limits`): mp4 или mov, не длиннее
  30 секунд, высота от 720. Диалог проверяет их до отправки, но окончательное
  решение остаётся за бэкендом.
- **`done_with_errors`** означает прогон, прошедший не в полную силу; причина —
  в баннере над таймлайном, а не в молчаливом успехе.

## Метрика «в три раза быстрее»

Ради неё в интерфейсе есть три вещи:

- **Отметка проверки** (`Y`) у каждого сегмента, счётчик в шапке, кнопки
  «Непроверенный» (`Shift+Tab`) и «Все». Правка отмечает сегмент заодно: чтобы
  его тронуть, надо было его увидеть.
- **Таймер активного времени**: считаются только секунды, когда вкладка на
  экране и была активность за последние тридцать. Иначе счётчик рос бы, пока
  человек пьёт кофе, и метрика показывала бы обратное тому, что мы доказываем.
- **Режим «с нуля»** — кнопка на карточке задачи. Прогноз скрывается, дорожка
  пустая, время идёт в отдельный счётчик. Это знаменатель: без замера ручной
  разметки отношение не с чем сравнивать. Такая правка намеренно не сохраняется
  поверх настоящей.

Результат виден на экране задач: медиана правки против медианы разметки с нуля.

## Проверки

```bash
npm test               # типы и 18 тестов на операции над дорожкой
npm run e2e:video      # тестовый ролик (нужен ffmpeg)

npm run dev:mock &     # прогоны против фикстур
npm run e2e            # правка, вырез, undo, экспорт
npm run e2e:scenarios  # обязательные состояния контракта §8

npm run e2e:live       # против живого пайплайна на :8000
```

`e2e:live` проходит полный путь: загрузка ролика, ожидание авторазметки, кадры с
сервера, отметка проверки, вырез середины, отправка правки.

Тестовый ролик кодируется в VP9, а не в привычном H.264: Chromium, который
поставляет Playwright, собран без проприетарных кодеков. На настоящих браузерах
такого ограничения нет.

## Структура

```
web/src/
  api/       types.ts — контракт; client.ts — транспорт; mock.ts — фикстуры
  lib/       segments.ts — чистые операции над дорожкой; export.ts, time.ts,
             useActivityTimer.ts — замер активного времени
  store/     tasksStore.ts — проекция серверного списка; editorStore.ts — undo/redo
  screens/   TasksScreen, CreateTaskDialog, EditorScreen
  components/ Timeline, VideoStage, KeyframePanel, SegmentInspector, RangePicker
  fixtures/  prediction_ok / _with_errors / _empty, vocab
```

Вся логика правки дорожки — чистые функции в `src/lib/segments.ts`: они не
мутируют вход, поэтому undo/redo хранит просто ссылки на снимки, а тесты не
требуют браузера.

## Ограничения

- Приём видео только загрузкой файла: ссылку на внешнее хранилище пайплайн не
  качает (открытый вопрос №2 контракта).
- Авторизации нет (открытый вопрос №3), `reviewer` зашит заглушкой.
- Иерархия шагов (`coarse` / `fine`) в интерфейсе не редактируется: пайплайн её
  пока не производит. Подшаги сохраняются при правке родителя и отбрасываются с
  явным сообщением, если он сдвинулся.
