# Praxis: как это запускать

Короткая инструкция для команды. Что и почему выбрано — в `docs/BOUNDARIES.md`,
требования кейса — в `docs/CASE.md`, что почитать — в `docs/READING.md`.

---

## Из чего состоит

Пять стадий. Главное архитектурное решение: **языковая модель не касается времени.**

```
кадры            ffmpeg, 16 fps
  ↓
признаки         TimeSformer-K400, окно 16 кадров, шаг 4  →  вектор на каждые 0.25 с
  ↓
границы          ядровой change-point со штрафом за сегмент  →  число шагов выводится само
  ↓
метки            Qwen3-VL, свободная генерация без словаря, 5 кадров + контекст «до/после»
  ↓
проверка         pydantic-схема и инварианты  →  выгрузка в контракт кейсодателя
```

Почему границы отдельно от языковой модели — это измерено, а не выбрано на вкус:

| способ | F1@0.5 | шагов на ролик | с/ролик |
| --- | --- | --- | --- |
| **ядровой change-point** | **0.507** | 3.3 | 0.4 |
| VLM прямым запросом | 0.541 при 3.9 шагах вместо 2.2 | 3.9 | 22.3 |
| VLM бинпоиском | 0.198 | 6.0 | 58.6 |
| прежний motion-dp | 0.429 | 2.5 | 0.4 |

VLM ставит границы точнее там, где попадает (1.44 с против 1.75 с), но пересегментирует
и стоит вдвое-впятеро дороже. Если сервис языковой модели упадёт, таймлайн всё равно
будет — деградирует только именование.

## Что поднять на GPU-машине

Три независимых сервиса, каждый на своей карте. Все говорят по HTTP, приложение об их
внутренностях не знает.

```bash
# признаки видео — нужен всегда
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=4 HF_HOME=~/praxis/hf \
    python scripts/serve_video.py --port 8102 --model timesformer

# именование — нужен для меток, без него будет только нарезка
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=2 HF_HOME=~/praxis/hf \
    python scripts/serve_vlm.py --port 8100 --model Qwen/Qwen3-VL-8B-Instruct

# обучаемый детектор границ — необязательный, экспериментальный
CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=5 \
    python scripts/serve_tas.py --port 8104
```

Перезапуск сервиса — **двумя разными ssh-вызовами**: остановка и старт. `pkill -f` в одной
команде со стартом убивает саму удалённую оболочку, потому что её командная строка
содержит имя скрипта; сервис гибнет молча, лог обрывается сразу после «готово».

```bash
ssh -n dl5 'pkill -f "serve_v[l]m"; until ! pgrep -f "serve_v[l]m" >/dev/null; do sleep 1; done'
ssh -n dl5 'cd ~/praxis && setsid nohup env CUDA_DEVICE_ORDER=PCI_BUS_ID CUDA_VISIBLE_DEVICES=2 \
    HF_HOME=$HOME/praxis/hf PRAXIS_VLM_MAX_IMAGES=20 venv/bin/python serve_vlm.py --port 8100 \
    --model Qwen/Qwen3-VL-8B-Instruct > logs/vlm.log 2>&1 < /dev/null & disown'
curl http://127.0.0.1:8100/health     # ждать снаружи, через туннель
```

Лог читать `grep -a`: прогресс-бар загрузки делает файл «бинарным», и обычный `grep`
прячет трейсбек. `PRAXIS_VLM_MAX_IMAGES` — потолок картинок на один проход именования;
именно он, а не число сегментов, определяет память карты.

`CUDA_DEVICE_ORDER=PCI_BUS_ID` обязателен: без него номер карты не совпадает с тем, что
показывает `nvidia-smi`, и легко занять чужую.

Если машина удалённая, порты пробрасываются туннелем:

```bash
ssh -N -L 8100:127.0.0.1:8100 -L 8102:127.0.0.1:8102 -L 8104:127.0.0.1:8104 \
    -o ServerAliveInterval=30 <хост>
```

## Что поднять локально

```bash
uv venv ~/.venvs/praxis && VIRTUAL_ENV=~/.venvs/praxis uv pip install -e .
cd web && npm install && npm run build          # редактор
PRAXIS_VIDEO_BASE_URL=http://127.0.0.1:8102 \
PRAXIS_VLM_BASE_URL=http://127.0.0.1:8100 \
    uvicorn praxis.api:app --port 8000
```

Либо целиком в контейнере: `docker compose up`.

## Настройки, которые действительно меняют результат

Всё через переменные окружения, значения по умолчанию выставлены по замерам.

| переменная | по умолчанию | что делает |
| --- | --- | --- |
| `PRAXIS_PIPELINE` | `tsm-kernel` | способ нарезки |
| `PRAXIS_TSM_PENALTY` | `2.0` | **главная ручка гранулярности**: больше штраф — меньше шагов |
| `PRAXIS_MIN_SEGMENT_SEC` | `0.5` | минимальная длина шага |
| `PRAXIS_IDLE_RATIO` | `0.0` | порог, ниже которого кусок считается паузой; ноль отключает |
| `PRAXIS_OPEN_VOCABULARY` | `1` | свободная генерация меток; при `0` ответ притягивается к словарю |
| `PRAXIS_LANGUAGE` | `ru` | язык ответов модели — должен совпадать с языком эталона |
| `PRAXIS_VLM_FRAMES` | `5` | кадров на шаг; **больше вредит**, см. ниже |
| `PRAXIS_CONTEXT_FRAMES` | `0.6` | на сколько секунд наружу брать кадры «до» и «после» |
| `PRAXIS_JOB_TIMEOUT_SEC` | `300` | предел на обработку одного ролика |
| `PRAXIS_GPU_HOUR_COST` | `60` | ставка за час GPU, из неё считается стоимость прогона |

### Два режима гранулярности

Оптимум резко зависит от того, насколько мелко размечает заказчик:

```bash
# атомарные действия: поднял, повернул, перенёс — 9 шагов по секунде (по умолчанию)
PRAXIS_TSM_PENALTY=2  PRAXIS_MIN_SEGMENT_SEC=0.5  PRAXIS_IDLE_RATIO=0

# крупные шаги: 2-3 действия по 6 секунд с паузами между ними
PRAXIS_TSM_PENALTY=8  PRAXIS_MIN_SEGMENT_SEC=1.5  PRAXIS_IDLE_RATIO=0.3
```

Это одна команда, а не переделка: гранулярность и была задумана как ручка.

## Как мерить

```bash
# метрика кейса целиком: один-к-одному, IoU >= 0.5, верный класс действия
python scripts/eval.py --gt data/pool_val/gt --pred work/pred

# сравнить несколько способов нарезки на одном наборе
python scripts/sweep.py --clips data/pool_val/clips --gt data/pool_val/gt \
    --methods baseline-uniform motion-dp tsm-kernel tw-finch

# только именование, на эталонных границах
python scripts/eval_naming.py --clips … --gt … --allowed … --soft

# демонстрационный ролик с дорожками эталона и нашей нарезки
python scripts/demo_video.py --clip … --gt … --pred "наше=…" --out demo.mp4
```

Признаки кэшируются на диск в `work/features`, поэтому повторный прогон и подбор
параметров идут почти мгновенно. Ключ кэша включает имя модели — при смене энкодера
пересчёт происходит сам.

## Что уже проверено и отклонено

Не тратьте на это время, всё измерено, числа записаны в коде рядом с флагами.

**Нарезка.** VLM бинпоиском (0.198 против 0.612), VLM прямым запросом (пересегментация),
рекурсивный разбор матрицы самоподобия (0.251), TW-FINCH (0.367), минимумы движения
(0.142), сетка признаков 8 Гц (дороже на 63% без выигрыша), подрезка краёв по активности
(ухудшает на щедрой разметке).

**Признаки.** VideoMAE, V-JEPA2, DINOv2 против TimeSformer — интервалы перекрываются
полностью, выбор энкодера почти не решает. TimeSformer оставлен как самый быстрый.

**Именование.** Двухступенчатая схема во всех трёх вариантах, контекст соседних шагов
текстом, подписи кадров, скоринг гипотез правдоподобием, совместный разбор ролика,
обрезка по треку SAM2, Grounding DINO, классификатор SigLIP2. И главное:
**восемь кадров вместо пяти роняют точность действия с 0.558 до 0.142** — не добавляйте
кадры.

**Сработало ровно одно:** контекстные кадры «до» и «после» шага, пара 0.426 против 0.386.
Прирост в пределах шума, но приём бесплатный по времени.
