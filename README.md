# Automarkup — предразметка действий по видео

Интерфейс для проверки и правки автоматической сегментации видео на действия.
Модель даёт черновик, человек за минимальное число движений доводит его до
разметки, пригодной для обучения роботов.

Собран против контрактов из `contracts.md` (`schema_version 1.0`).

## Быстрый старт

```bash
npm install
npm run dev          # http://localhost:5173
```

По умолчанию UI работает против **мока с фикстурами** — ни бэкенд, ни ML для
запуска не нужны. Реальный бэкенд подключается одной переменной:

```bash
VITE_API_BASE=https://api.example.com npm run dev
```

Больше в коде ничего менять не требуется: `src/api/client.ts` — единственное
место, знающее про транспорт.

## Два экрана

**Список задач.** Карточка показывает словарь действий, длину ролика и статус
авторазметки. Загруженное видео сразу уходит в очередь; задача открывается,
когда прогноз готов. При создании можно взять общий словарь, ранее сохранённый
или ввести новый (по одному классу в строке, либо `pick — Взять` с явным id).

**Экран разметки.** Видео слева, таймлайн под ним, рабочая панель справа.

## Как правится разметка

Принцип из кейса: граница, действие, объект и ключевой кадр правятся
**независимо** — единой кнопки «переделать всё» нет.

| Задача | Как |
|---|---|
| Найти нужный кадр | колесо над таймлайном — масштаб от всего ролика до 0,4 с в окне |
| Прокрутка при зуме | `Shift`+колесо, перетаскивание ПКМ, обзорная полоса сверху |
| Пробежать разметку глазами | панель ключевых кадров: клик по кадру выделяет сегмент и прыгает на него |
| Разрезать сегмент | поставить курсор и нажать `S` |
| **Вырезать середину** | инструмент «Вырезать» (`C`), протянуть по нужному куску — даже поверх существующих сегментов — и выбрать класс во всплывшем окне |
| Сдвинуть границу | тянуть за край сегмента, либо ввести таймкод в инспекторе |
| Сменить класс | цифры `1`–`9` или чипы в инспекторе |
| Отменить | `Ctrl+Z` / `Ctrl+Shift+Z`, история на 100 шагов |

Вырез — главный инструмент: диапазон может накрывать несколько сегментов и
дыры, всё перекрытое подрезается, полностью накрытое удаляется, на месте выреза
появляется один новый сегмент с выбранным классом.

### Горячие клавиши

`Пробел` играть/пауза · `,` `.` кадр назад/вперёд · `←` `→` ±1 с (`Shift` ±5 с) ·
`Tab` следующий сегмент · `S` разрезать · `C` / `V` инструменты · `F` приблизить
сегмент · `0` весь ролик · `+` `−` масштаб · `1`–`9` действие · `Del` удалить ·
`Ctrl+Z` отмена.

## Что взято из контракта

- **Время** — только целые миллисекунды, нигде не кадры и не float.
- **Сегменты** не пересекаются, отсортированы, дыры между ними разрешены —
  правка границы не двигает соседа каскадно.
- **`unknown`** — значение словаря, а не `null`.
- **Confidence по полям**: подсвечивается отдельно у действия, объекта и границы;
  сегменты с низкой уверенностью штрихуются прямо на таймлайне.
- **Значение вне словаря** показывается как есть с предупреждением — UI не падает
  и не подменяет его на `unknown`.
- **`keyframe_ms: null`** — валидное состояние: сегмент рисуется, кадр помечен
  как непосчитанный, бесконечного спиннера нет.
- **Пустой `segments`** — валидный результат, а не ошибка: ролик можно разметить
  с нуля вручную.
- **Prediction неизменяем**: правки живут отдельно, экспортировать можно и
  исходный прогноз, и правку.
- **Поллинг** — 2 с, бэкофф до 10 с после первой минуты, после 10 минут показываем
  «долго» и кнопку отмены, но джобу не убиваем.
- **Дифф с прогнозом** (границы, действия, объекты, кадры, добавленные и
  удалённые) считается в реальном времени и уходит в review вместе с
  `time_spent_ms` — это база для метрики «≥ 3× быстрее разметки с нуля».

Экспорт: JSON и CSV, `source=review|prediction`. CSV — UTF-8 с BOM,
фиксированный порядок колонок; для `source=review` колонки confidence пустые.

## Проверки

```bash
npm test              # типы + 18 тестов на операции над сегментами
npm run e2e:video     # записать тестовый ролик (нужен Chromium от Playwright)
npm run e2e           # сквозной сценарий: создание задачи → правка → экспорт → review
npm run e2e:scenarios # обязательные сценарии контракта §8
```

`e2e:scenarios` прогоняет то, что должно работать до подключения бэкенда:
пустой результат, `done_with_errors` с пропущенными keyframe, упавшая джоба,
обработка дольше 10 минут, перезагрузка страницы.

## Структура

```
src/
  api/       types.ts — контракт; client.ts — транспорт; mock.ts — фикстурный бэкенд
  lib/       segments.ts — чистые операции над дорожкой; frames.ts, export.ts, time.ts
  store/     tasksStore.ts, editorStore.ts (undo/redo)
  screens/   TasksScreen, CreateTaskDialog, EditorScreen
  components/ Timeline, VideoStage, KeyframePanel, SegmentInspector, RangePicker
  fixtures/  prediction_ok / _with_errors / _empty, vocab
```

Вся логика правки дорожки — чистые функции в `src/lib/segments.ts`: они не
мутируют вход, поэтому undo/redo хранит просто ссылки на снимки, а тесты не
требуют браузера.

## Ограничения

- Видео хранится только в текущей вкладке (`blob:`-URL). После перезагрузки
  разметка, таймлайн и экспорт продолжают работать, а файл предлагается выбрать
  заново — сервера для видео пока нет (открытый вопрос №2 контракта).
- Мок держит состояние джоб в `localStorage`, чтобы задачи открывались после
  перезагрузки. Реальному бэкенду это не нужно.
- Авторизации нет (открытый вопрос №3), `reviewer` зашит заглушкой.
