настоящий Chrome, наш снятый ролик `test_bottle.mp4` (30 с, 720p).

## Прогон на живых сервисах

Туннель до DL5, три сервиса, тот же Chrome-сценарий на `test_bottle.mp4`: 15 шагов с
метками модели («положил руку», «повернул бутылку», «вылил воду», «взял бутылку»,
«опустил руку»), превью кадров, отметка проверки, правка, сохранение, повторное открытие
на правке. Через API на `test_combined.mp4` (36 с): 16 шагов, 76 с после расширения батча VLM до
20 картинок (было 92), `warnings: []`, стоимость посчитана из GPU-секунд. Уверенность — самооценка модели из её ответа,
не константа; при отсутствии — `null`. Ограничение: модель оценивает себя на 0.95–1.0
почти всегда, калиброванной уверенности на шаг у нас пока нет — подсветка «неуверенных»
шагов в редакторе работать не будет, пока не появится сигнал вроде согласия нескольких
прогонов или запаса логитов.

Повторить: `cd web && PLAYWRIGHT_CHROMIUM_PATH=/usr/bin/google-chrome npm run e2e:live`
(ожидание готовности в сценарии — 240 с, под живой прогон).

## Что не проверено и почему

- **libx264 обязателен.** См. `PIPELINE.md`: без него нарезка молча деградирует
  до одного шага. Проверяется одной командой.
- **`docker build`.** На этой машине нет демона. Сборка образа проверяется на площадке.
- **GPU на площадке.** Признаки, детектор и именование живут на DL5. Без VPN пайплайн
  честно деградирует, но качество — серые блоки и `unknown`. Нужен либо VPN, либо
  сервисы на месте: три процесса, `scripts/serve_video.py`, `scripts/serve_tas.py`,
  `scripts/serve_vlm.py`.
